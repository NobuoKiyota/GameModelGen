## 4. 座標系・スケール（`AnimeFace/lib/common.py`）
- 単位 m。**1px = 0.0007 m**（下絵 1024² = 0.7168 m）。顔は **-Y 向き**。X=0/Y=0 は下絵の中心列（col 512）。**Z=0 は瞳の中心の行（row 518.5）**。
- 正面 px→3D: `X=(u-512)*K, Z=(518.5-v)*K`。側面: `Y=-(u-512)*K`（顔が右向き＝-Y）。視点角 a の投影: `u=512+(x cos a − y sin a)/K, v=518.5−z/K`。
- 頭は前後左右ほぼ対称の球（Z≈0.086 が中心、半径≈0.231、頭頂 Z≈0.29）。額の上端 Z=+0.19。
- 下絵: `textures/human/chibi_blueprint_{front,45deg,side}.png`（1024²、3枚とも RGBA/RGB）。**高さの正は正面＋側面**（目は1px以内で一致）。45° は目まわりの形の参考のみ（鼻・口の前後位置には使わない）。
- 下絵どうしの食い違い（正面/45°/側面）: 口の線の中心 723/709/677、鼻先 618(点)/629/591、顎の底 829/約795/約818。**鼻は「正面の点＝鼻先と鼻下の中間」なので側面の輪郭をそのまま使う**。

## 6. 重要な教訓（詳細は `LEARNINGS.md`）
1. **範囲を取りこぼさない**: 字幕のタイムスタンプ→実装項目を先に表にする。
2. **測定ゲートは画像から毎回再測定**し、定数との比較だけにしない。レビュー画像の目視で、測定ミスが見つかることが多い（側面の目の開口、鼻の点＝鼻先と鼻下の中間 など）。
3. 下絵は3視点で食い違う。高さの正は正面＋側面、鼻は側面、45°は形の参考。生成AIに下絵を作り直させない。
4. **Subsurf は鼻先を12mm・顎先の角を7mm鈍らせる** → サポートループ＋鼻先0.5mm・顎先約9mm（斜め）の補正。補正量は要確認事項として報告。
5. 頭の表面は、測定した前後の輪郭 A(Z)/Bf(Z)/Bb(Z) で表現（楕円体は額〜頭頂のみ近似）。頭頂真上の光線は表面に届かない（Z>頭頂は外側とする）。
6. **凹んだ角（外側270°）は4辺の格子では埋められない** → 折れた面を削除し、ユーザーが手で埋める。孤立した三角形を四角形1枚ぶん動かす操作は、曲がった面で四角形が折れるので使えない。
7. bmesh の落とし穴: `subdivide_edges`/`verts.new` 後は `ensure_lookup_table()`、`bm.free()` 後は BMVert 参照不可、頂点削除で番号が詰まる（BMVert を保持して `is_valid` を確認）、`bmesh.ops.grid_fill` は黙って失敗する（`bpy.ops.mesh.fill_grid` は動く）、Blender の座標は単精度（許容値 1e-6 m）。
8. Workbench の最初のテクスチャ付き描画は白紙になる（捨て描画を1回）。
9. 人間が編集した `.blend` は編集モードのまま保存されていることがある（読み込み側で Object モードへ戻す）。
