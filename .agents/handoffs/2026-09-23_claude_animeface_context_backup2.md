## 3. 今回のセッションで起きた「生成側のバグ」と教訓（再発防止のため必読）

### 3.1 bmesh の `.index` は `ensure_lookup_table()` だけでは更新されない
新しく作った頂点・面の `.index` は `-1` や古い値のままになり、それに気づかず選別コードを書くと **Blender がネイティブクラッシュ**する（S14b）。`ensure_lookup_table()` と `index_update()` を必ずセットで呼ぶ。

### 3.2 オブジェクトの変換（位置・回転・拡大）を見落とすと、座標系がずれて処理が暴走する
人間が手直しでオブジェクト単位の移動・拡大（特に非一様拡大）を付けると、そのオブジェクトの頂点ローカル座標を他オブジェクト（ワールド座標）とそのまま比較する処理は破綻する（S15c、`DoubleLid` の頂点が数十mm飛んだ）。**オブジェクトを触る前に `obj.location`・`obj.scale`・`obj.rotation_euler` を確認し、単位でなければ `obj.data.transform(obj.matrix_world)` で焼き込んでから単位行列に戻す**。

### 3.3 「顔の面に近づいたら押し戻す」系の能動的補正は、判定方法が不正確だと暴走する
BVHTree.overlap による三角形の重なり判定は、離れた面どうしでも「近接」で誤検出することがある（main lash 自身の既知良品でも誤検出した）。**間引き・単純化のような「形を変えないはず」の操作では、能動的に動かす補正は避け、「元の形（承認済み）自身を基準に、悪化していないか比べる」方式**のほうが安全。

### 3.4 細い付属物（房・毛）は、直線の折れ線でなく、なめらかな曲線で作る
房（S14b）の1回目は、3輪・直線2本の中心線で、まっすぐな針に見えた。断面5輪を2次ベジエでなだらかに曲げ、太さも滑らかに変化させるよう修正。**曲げの向きは、正面から見た平面（X-Z）内に限定する**（奥行き方向に曲げると、正面から見て輪・ループのように見える）。

### 3.5 下絵の線画は画素単位でがたつく（測定してそのまま使うと形もがたつく）
眉の輪郭で標準偏差1.8px・最大7px。**移動平均で均してから使う**（動画の人間作業が少ない頂点で滑らかなのは、目で見て暗黙に均しているから）。

### 3.6 UV関連の演算子は `--background` 実行では動かない
`bpy.ops.uv.unwrap`・`smart_project`・`pack_islands` は、ウィンドウ（3Dビュー）がないため内部で失敗し `{'CANCELLED'}` を返す（UVレイヤーが作られない、または座標が更新されない）。**UV座標は演算子を使わず、頂点の3D位置から直接、数式（投影・パラメータ化）で計算する**（S16）。

### 3.7 房・小さい付属物の配置は、自動化での成功率が低い
房の位置・曲がり方を、動画のように「外眼角側にまとめる」よう2回自動で試したが、いずれもユーザーに「良くなっていない／ぐちゃぐちゃ」と判断された（S15b、その後の再挑戦）。**この種の見た目重視の細部は、人間が手で調整する方が早く正確**という結論に達している。房は現在、S14b2時点の人間の手直し位置のまま。

## 4. 座標系・作り方の要点（再掲。詳細は `lib/common.py`・`DESIGN.md`）
- 単位 m。1px = 0.0007m（下絵1024²）。顔は -Y 向き。Z=0 は瞳の行。
- 半分（X≤0）だけを作り、Mirror(X, Clipping, Merge) → Subsurf(表示1/レンダー2) の順で、Apply しない。
- 帯状の付属物（まつ毛・眉・二重線・房）は、共通して「駅（4頂点: 外側O・前の稜F・内側I・後ろK）× N」の断面パラメータ化で作っている。UVもこの構造を直接利用（S16）。
- クリース（`crease_edge`属性）とシャープ（`sharp_edge`属性）は、帯の前の稜に1.0を付け、全体をスムースシェードにする。
