## 1. ノードの本質：「白と黒（0.0〜1.0）の数値データ」による範囲指定（マスク）

Blender のシェーダーノードやジオメトリノードを難しく感じる最大の原因は、「ノードが画像や色を扱っている」と錯覚してしまうことです。
ノードの本質は **「0.0（完全な黒）〜 1.0（完全な白）の数値情報の受け渡しと計算」** です。

```
0.0 (黒) ────────────────── 0.5 (灰) ────────────────── 1.0 (白)
[効果 0% / なし]              [効果 50%]              [効果 100% / 最大]
[Mix の 入力 A]                                       [Mix の 入力 B]
[Roughness ツルツル]                                  [Roughness ザラザラ]
[凹み・溝]                                            [隆起・山]
```

- **テクスチャ（Noise, Voronoi, Checker, Wave等）の役割**:
  - 色を塗っているのではなく、**「どこに効果を出すか」という0〜1のグラデーション範囲（マスク）** を自動生成している。
- **ColorRamp（カラーランプ）の役割**:
  - 生成された 0〜1 の数値を、人間の好みの色相や、より急峻なしきい値（ハイコントラスト）に**再マッピング（補間変換）** している。

## 2. ソケットの色とデータ型（色の互換性と自動変換ルール）

ノードの入出力端子（ソケット）は、流れるデータの型によって厳密に色分けされています。

| ソケット色 | データ型 | 内容と例 | 他ソケット接続時の挙動 |
|---|---|---|---|
| ⚪ **灰色 (Gray)** | `Float` (単一数値) | `0.5`, `1.0`, `Fac`, `Roughness`, `Metallic` など | Colorに繋ぐと `(V, V, V)` のグレースケールになる。Vectorに繋ぐと `(V, V, V)` になる。 |
| 🟡 **黄色 (Yellow)** | `Color` (RGBA 4値) | `(R, G, B, A)` 色情報、テクスチャカラー | Floatに繋ぐと **RGBの輝度平均** `(0.2126R + 0.7152G + 0.0722B)` に変換される。 |
| 🟣 **青紫 (Purple)** | `Vector` (XYZ 3値) | `(X, Y, Z)` 座標、法線(Normal)、オフセット | Colorに繋ぐと `(X→R, Y→G, Z→B)` として可視化される（法線マップ表示など）。 |
| 🟢 **緑色 (Green)** | `Shader` (計算閉包) | `Principled BSDF`, `Glass BSDF`, `Emission` | **Shader同士しか接続できない**（Mix Shader や Add Shader でのみブレンド可能）。数値や色を直接繋ぐことは不可。 |

## 3. ミックスノード（Mix / MixRGB）の仕組みと塗り分けの極意

マテリアル制作の8割は **「Mixノードに何を繋ぎ、Fac（係数）でどう塗り分けるか」** に集約されます。

### 基本構造
```
[入力 A (上)] ────┐
                  ├─── [Mix Node] ───► 出力 (合成結果)
[入力 B (下)] ────┤        ▲
                  │        │
               [Fac] ──────┘ (0.0=A, 1.0=B)
```

- `Fac = 0.0` のとき: **100% 入力 A**（上の色・値）
- `Fac = 1.0` のとき: **100% 入力 B**（下の色・値）
- `Fac = 0.5` のとき: **A と B が 50% ずつ混ざる**

### 実践：マスクテクスチャによる塗り分け
`Fac` に Noise Texture や Checker Texture（白黒データ）を接続すると：
- **黒い部分（0.0）** → 入力 A（例：錆びた鉄、濡れた土、暗いモルタル目地）
- **白い部分（1.0）** → 入力 B（例：金色の塗装、みずみずしい緑の芝生、乾燥した石肌）

## 4. 座標系（Texture Coordinate）の完全理解

テクスチャをどこを基準に貼り付けるかを決定する最重要ノードです。

```
[Texture Coordinate]
 ├─ Generated : オブジェクトのバウンディングボックス基準 (最小角が 0.0, 最大角が 1.0)
 ├─ Normal    : 面の向き (法線ベクトル)
 ├─ UV        : 展開された UV マップ (2D平面 0.0〜1.0)
 ├─ Object    : 【最推奨】オブジェクトの原点 (中心) が (0,0,0)。スケール変形に強い。
 ├─ Camera    : カメラの視点基準
 └─ Window    : 画面スクリーン基準 (2D UI的)
```

### なぜ `Object` 座標がプロシージャルで最も多用されるのか？
1. **形状変形に強い**: オブジェクトのサイズを伸ばしても、テクスチャが引き伸ばされず均一な密度を維持しやすい。
2. **原点が中心**: `(0, 0, 0)` が中心にあるため、球面・回転・対称の数学的計算が極めて直感的に行える。
3. **シーム（切れ目）がない**: 3D 空間全体にノイズが詰まっている（ボクセル的）ため、UV 展開の継ぎ目を気にする必要がない。

## 5. 軸分離（Separate XYZ）と合成（Combine XYZ）による高度な空間制御

### Separate XYZ による「高さ」「向き」の制限
`Vector`（紫）から特定の一方向だけを `Float`（灰）として取り出す手法です。

1. **Z軸分離（高さグラデーション / 積雪 / 水位）**:
   - `Separate XYZ` の `Z` 出力を ColorRamp に繋ぐと、下から上へのきれいなリニアグラデーションが得られる。
   - 例: 「ビルの下層階だけ汚れをつける」「山の標高が高い部分だけに雪を積もらせる」「草ブレードの根元だけ濃い緑にする」。
2. **Y軸 / X軸分離**:
   - 板ポリゴンの進行方向グラデーション（葉の先端/根元判定）。

### Combine XYZ
X, Y, Z を個別の数値・波形で制御し、最後に合体してテクスチャ座標として再入力することで、**「水面の波打ち」「風による揺らぎ」「ねじれ座標」** を生み出します。

## 6. テクスチャ多重ブレンドの応用技法

1つのテクスチャだけでは幾何学的・機械的な不自然さが残ります。プロシージャルでは **複数のノイズを階層的に合成** します。

```
[大スケール Noise] (大きなうねり・形状の塊)
         │
         ▼ (Multiply または Overlay)
[小スケール Noise] (表面の微細なザラつき・風化)
         │
         ▼
[ColorRamp] (コントラスト調整) ──► Bump / Roughness / BaseColor
```

- **Musgrave / Noise の掛け算 (MULTIPLY)**:
  - 広大な大地の中で「一部のエリアだけに岩肌を露出させる」ような不均一なムラを作る。
- **ベクトルディストーション (Vector Distortion)**:
  - Mapping ノードとテクスチャの間に Noise Texture を挟む（座標にノイズを足す）ことで、直線のテクスチャ（木目や地層、タイル目地）をランダムにグニャリとうねらせる。

## 7. Blender Python (bpy) でのシェーダー自動構築ベストプラクティス

Python API でプロシージャルノードを動的生成する際の鉄則：

```python
# 1. ノードツリーの初期化
mat.use_nodes = True
nodes = mat.node_tree.nodes
links = mat.node_tree.links
nodes.clear()

# 2. ノードの新規作成と位置指定（横方向に整列させるとデバッグしやすい）
node_coord = nodes.new('ShaderNodeTexCoord');    node_coord.location = (-1000, 0)
node_noise = nodes.new('ShaderNodeTexNoise');    node_noise.location = (-700, 0)
node_ramp  = nodes.new('ShaderNodeValToRGB');    node_ramp.location  = (-400, 0)
node_bsdf  = nodes.new('ShaderNodeBsdfPrincipled'); node_bsdf.location = (0, 0)
node_out   = nodes.new('ShaderNodeOutputMaterial'); node_out.location  = (300, 0)

# 3. バージョン差異を吸収する Mix ノードヘルパーの使用
# Blender 3.4以降は ShaderNodeMix (data_type='RGBA') に統一されている
from .helpers import get_mix_input, get_mix_output
```
